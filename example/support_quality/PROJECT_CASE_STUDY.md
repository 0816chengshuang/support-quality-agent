# 演示案例：从工单统计到证据核对

## 我们解决的问题

主管问“超时率多少”时，真正需要的不只是一个百分比：时间范围要明确，超时和有效工单的定义要一致，分类追问要沿用已确认条件，规则解释要有出处，原始数据也要能回查。项目针对**口径漂移、无依据回答和会话条件串用**做了一套小型 Agent 应用闭环。

固定报表适合重复查看预设指标；本项目适合临时修改条件、连续追问定义、补齐缺失条件和切换到原始记录审计的场景。所有数据均为合成样本，用户看到的是可重复的演示，不是企业实时看板。

## 现场演示

先按[仓库首页](../../README.md#本地演示)启动，在 [本机页面](http://127.0.0.1:8501/)新建对话。每一步等上一步完成后再发送：

| 步骤 | 输入 | 观察点 |
| --- | --- | --- |
| 1 | `统计 2026-10-01（含）到 2026-10-08（不含）新建工单的超时率，使用 UTC，按整体统计，不筛类别。` | 固定口径工具返回 **40%（4/10）**，展示日期、观察截止、分子分母与规则版本。 |
| 2 | `保持刚才日期和口径，按类别拆开看。` | 账号 **3/4**、账务 **0/2**、配送 **1/4**；整体比例不是三个百分比的简单平均。 |
| 3 | `超时率分母包括未解决工单吗？请查规则并给出处。` | 规则检索返回中文原文、`source_ref` 和 `chunk_id`；没有把模型的记忆当来源。 |
| 4 | `请查询合成工单原始表中的最大 id，包括测试、重复、已取消记录，不作业务排除、不限制日期。给出真实 SQL 和查询结果，不要图表。` | 进入 SQL 专项子流程，实际执行只读查询，预期 `MAX(id)=15`；原始审计不套用指标排除条件。 |
| 5 | 新建另一对话，输入 `这周超时率多少？` | 系统先要求明确 UTC 起止日期，不沿用旧对话的历史范围或旧结果。 |

还可以在新对话输入 `统计超时率` 测试缺少日期的澄清与恢复，或问 `退款审核需要几个工作日？` 检查资料未命中时是否拒绝编造答案。左侧历史列表可以切回旧对话；执行过程显示实际工具步骤，但不是模型内部思维的完整证明。

## 解决方案与取舍

1. **稳定数字：** 用预定义指标 Skill 固定三项口径；模型填时间、类别等参数，程序校验后运行参数化只读 SQL，并展示本轮真实数值。这样可针对错误分母、空数据和日期越界写确定性测试。
2. **有据可查：** 将业务规则按章节切分并接入检索工具，默认 BM25，保留可选本地向量路径；返回原文及来源编号。未命中与检索失败分开，不让模型补写不存在的规则。
3. **控制上下文：** 会话状态支持继续追问与待补充任务恢复；相对时间先澄清，新会话不继承旧范围，且新答案必须有本轮执行证据。
4. **区分查询目的：** 固定指标走规则化计算；原始记录核对走 SQL 专项子流程，保留用户要求的包含范围。两条路径各有边界，不能把原始 `MAX(id)` 误说成通用计数算法。
5. **限制成本与权限：** 演示只用本机模型、只读数据库和受限工具集合；单次模型调用有超时、输出上限且不自动重试。没有付费 API 回退，也没有声称全链路的并发控制。

## 能说明哪些技术

| 技术点 | 可演示的具体行为 |
| --- | --- |
| 工具调用与工作流 | 模型提出结构化参数，程序校验后执行；缺条件暂停，完成后根据本轮结果返回。 |
| Skill 与业务契约 | 三指标有明确输入、公式、输出和失败状态，避免临时改口径。 |
| 检索增强 | Markdown 分块、BM25、可选本地向量、top-k/上下文预算及来源引用。 |
| 会话与运行约束 | 历史恢复、任务继续、工具范围、只读访问、错误状态和证据门槛。 |
| 有限角色协作 | 原始审计由主对话交接到 SQL 专项子流程；指标问题不经过多个 Agent。 |
| 测试与故障复盘 | 固定口径/边界测试、真实本机网页回放，以及“这周”误用旧日期后的修复。 |

## 验证与边界

离线回归已运行 **360 项**；本机真实网页曾完成整体、分类、规则引用、会话恢复和原始 SQL 核对。离线替身不证明模型质量；向量检索只有六个小样本的独立测试，网页默认仍是 BM25。15 条记录用于边界测试，不支持生产准确率或吞吐结论。本机 `.run/` 保存历史运行材料但被 Git 忽略，不作为公开仓库自带证据；公开复现应按本页步骤重新操作。

项目没有正式多租户权限、完整 SQL 沙箱、动态 Skill 发现或通用自主多 Agent 规划。网页没有端到端 p95、并发吞吐或生产成本数据。技术介绍应围绕上表中实际完成的行为，不把底层框架能力、示例数据量或单机结果扩大为线上成果。

## 简历表述参考

> 围绕工单复盘中的统计口径漂移和无依据回答，设计三指标 Skill 与参数化只读查询，使模型负责理解与填参、程序负责规则计算和证据展示；支持连续分类追问及缺参澄清。

> 为业务规则补充 Markdown 分块检索、BM25/可选本地向量路径、来源引用与上下文预算；修复相对时间误用旧范围和原始审计误套指标规则的问题，并用离线回归和本机网页核对统计与 SQL 结果。
