# 工单质量分析演示

这是基于 [OpenChatBI](https://github.com/zhongyu09/openchatbi) 的本地改进，不是从零实现的 Agent 平台。
上游版本与 MIT 许可见 [UPSTREAM.md](../../UPSTREAM.md)，当前验收边界见 [ACCEPTANCE.md](../../ACCEPTANCE.md)。

先了解产品而非代码：[产品理解与操作逻辑](./PRODUCT_GUIDE.md)，包含用户场景、截图数字含义、两条查询路径、技术对应及当前边界。
准备项目经历时看[项目陈述与证据](./PROJECT_CASE_STUDY.md)：逐项标明上游能力、本地改进、可演示知识点及不能声称的内容。

## 场景和特色

客服主管希望核对“这段时间处理得怎么样、哪个类别超时更多、这个比例怎么算”。
直接让模型写 SQL 容易猜错时间、分母和排除条件，单纯贴一个数字也难以核对。

本轮只交付这一条闭环：

1. 指标、日期不明确时，先暂停询问；补充后继续原任务。
2. 三个约定指标由可复用 Skill 执行参数化只读查询，不让模型临时决定计算公式。
3. 同会话可以沿用日期按类别追问；新会话没有旧条件时不能假装记得。
4. 查规则返回相关 Markdown 片段和真实来源，不用整段 glossary 代替检索。
5. 原始 SQL 审计走主助手 -> 原 Text2SQL 子图，不误套业务指标的排除规则。
6. 展示实际结果和依据；缺资料、检索失败、查询未执行是不同状态。

本地贡献是指标契约、资料检索、可选 Skill、工具范围约束、证据展示和针对性测试。
原 LangGraph 主循环、Text2SQL 子图、checkpoint、ToolNode、Streamlit 页面属于上游能力。

## 现在如何操作

先按[仓库首页](../../README.md#本地演示路径)准备合成数据并启动页面，然后打开 [http://127.0.0.1:8501/](http://127.0.0.1:8501/)。在底部输入问题并发送；不需要 API 密钥，Ollama 须保持运行。

1. 点左侧“新建对话”，使用独立 Session ID，不会删除旧会话。
2. 输入下面表格第 1 步的完整问题，等返回 40%（4/10），再连续输入第 2、3 步。
3. 展开“执行过程”可看中文工具步骤；答案正文显示真实查询结果或规则片段/引用。
4. 测试缺条件时先新建对话，再输入“帮我看看工单质量。”，随后补齐第 1 步条件。
5. 想回到旧会话，直接点击左侧“历史对话”的标题；新建对话不删除旧记录，刷新后列表仍可从已有 checkpoint 恢复。列表按最近活动排序，最多展示当前“用户标识”的 50 段有提问记录的对话。也保留“会话编号”手工恢复入口。

本轮已在实际浏览器用真实本机模型检查统计、分类追问、规则出处、新对话/历史、待补充任务恢复和 SQL 子流程查询 MAX(id)=15。使用 qwen2.5:3b / BM25 / 合成只读 SQLite，不产生付费 API 请求。CPU 首次加载较慢，单次模型调用可能数十秒，SQL 多步骤更久；提问期间不要反复点击发送。

### 开发侧回归（不是网页入口）

以下独立 CLI 验证不会启动页面、模型服务或下载权重。
既有 Ollama 应用须正常运行，已安装的模型为 qwen2.5:3b；不需要 API 密钥，不会付费回退。

在 PowerShell 执行：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m openchatbi.local_graph_smoke --configured-tools
```

这会按下面的用例提问、实际调用原图/工具/只读数据库，并输出每步 PASS / FAIL。
完成后看：

- .run/local-graph-configured.md：可读回放，含输入、工具、结果及暂停信息。
- .run/local-graph-configured.json：完整参数、工具结果、执行依据、检查与本机请求数。
- 非零退出码表示没有全部通过，不能仅凭模型回答“成功”判断通过。

模型在 CPU 上运行，每次执行可能需要数分钟；耗时不是生产性能指标。
只复测局部时可加 --scenarios，例如：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m openchatbi.local_graph_smoke --configured-tools --scenarios overall followup raw
```

### 自主提问的数据范围

2026-10-23 对实际演示 SQLite 只读核对：共 15 条合成工单，原始创建时间最早
2026-09-30 23:59:59、最晚 2026-10-08 00:00:00，统一 UTC。
主要演示区间是 2026-10-01 至 2026-10-07；统计结束日期最多填 2026-10-08，
但不包含该日。起始日前的范围可以查询，但没有记录的部分不会凭空补数据；
并非只允许 10 月 1 日作为开始日期，窗口仍受最多 93 天限制。
原始表还故意保留观察点之后的解决/取消事件用于边界测试，不代表统计已更新到这些日期。

查询一天：例如开始 2026-10-03、结束 2026-10-04。查询多天：自行选择起止日期，结束不包含。
可以组合：工单数量 / 超时率 / 平均处理时长，整体 / 按类别 / 筛选指定类别。
类别为 account（账号）、billing（账务）、delivery（配送）；筛选时附实际类别编码可减少歧义。
当前没有客服姓名、地区、金额等字段，不能假装支持相应分析。

### 标准回放

所有日期均为 UTC，开始包含、结束不包含；观察截止为 2026-10-08 00:00:00。
这是固定的合成案例，不使用当前电脑日期或真实公司数据。

| 步骤 | 输入 | 预期 |
| --- | --- | --- |
| 1 | 统计 2026-10-01 到 2026-10-08 新建工单的超时率，整体、不筛类别 | 有效 10、超时 4，40%；日期、分子分母和口径可见 |
| 2 | 保持刚才日期和口径，按类别拆开看 | account 75%（3/4）、billing 0%（0/2）、delivery 25%（1/4） |
| 3 | 超时率分母包括未解决的工单吗？查规则、给出处和 chunk_id | 实际检索的规则原文；分母含已解决和未解决的有效工单 |
| 4 | 退款审核需要几个工作日？资料没有就直说 | 真实检索未命中，不猜时限、不伪造来源 |
| 5 | 帮我看看工单质量；暂停后补充第 1 步的完整条件 | 先 AskHuman，补充后恢复，实际查询得到 40% |
| 6 | 同日期的平均处理时长 | 已观察解决 6 条，合计约 4800 分钟，平均 800 分钟 |
| 7 | 统计 2026-10-10 到 2026-10-11 的超时率 | 超出合成数据观察范围，不给成功数字 |
| 8 | 在新会话说“沿用刚才日期按类别拆开” | 要求补充，不泄漏另一会话条件 |
| 9 | 原始表最大 id，包含测试、重复、已取消记录，不限日期 | 主 -> SQL 子图真实执行；MAX(id)=15，SQL 与 CSV 可见 |
| 10 | 有历史统计后问“这周超时率多少？” | 不继承旧日期/旧结果；先询问 UTC 起止日期并提示演示数据截止；补明确日期后恢复 |

合成数据共 15 条，含测试/重复/取消、未解决及时间边界；文件为 fixture.sql。
整体比例不能直接平均分类比例；未解决工单不按 0 分钟混入平均时长。

## 检索与向量验证

默认 BM25，不消耗 embedding API。章节分块返回 source_ref、chunk_id、行号和内容版本；
限制资料目录、文件/分块数、top-k 与返回上下文，内容变更会使缓存失效。
no_match 不等于现实不存在该规定；retrieval_error 不能回答成“没有资料”。

真实本地 embeddinggemma:300m 已下载，768 维检索的 6 个小样本为 Top-3 命中 6/6、Top-1 命中 5/6；
不是生产准确率。独立证据为 .run/local-retrieval-smoke.json。
原图向量链路可单独验证，不修改默认 BM25 配置：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m openchatbi.local_graph_smoke --configured-tools --vector --scenarios definition
```

向量结果与回放为 .run/local-graph-vector.json / .md。
模型和 embedding 均固定本机端点；诊断限制次数、请求超时和总时长，不是全应用费用系统。

## 实现边界

- 工具按明确任务词缩小范围，属于程序路由，不是通用语义理解或自主规划。
- 模型填参数并调用工具；统计/SQL 最终展示由真实结果生成，规则采用带引用的原文片段，避免再生成矛盾结论。
- 原始 SQL 的上下文锚定用户真实请求；单个已核验目录表可确定性选表，记录来源，不硬编码 SQL 或答案。
- main -> Text2SQL 是有限职责交接，不是复杂自主 Multi-Agent；固定 Skill 不是动态 Skill 市场。
- 仅约定 SQLite schema；窗口最多 93 天、最多 20 组。只读连接与工具限制不等于完整 SQL 沙箱、多租户权限或查询超时。
- 不纳入本轮：多模态、复杂记忆、动态 Skill/MCP 平台、Python 分析、预测、图表/报告下载和生产部署。
- 原 6 次与追加 5 次付费额度已全部占用。API 连通/工具调用曾成功，完整 API SQL 未通过；本轮没有新增付费请求。
