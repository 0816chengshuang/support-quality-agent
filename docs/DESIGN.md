# 设计说明：工单质量分析助手

## 问题与目标

客服或运营主管在复盘工单时，常常要先看整体指标，再追问类别差异，最后核对统计规则与原始记录。把所有问题都交给模型自由回答，会出现三类错误：沿用过期日期、临时改变分母、没有查询依据却给出确定数字。项目目标是把一次提问收敛为**确认范围、选择能力、执行、核验证据、展示或澄清**的闭环。

当前数据为 15 条合成工单，特意覆盖未解决、取消、测试、重复、期限边界等情况。它用于检验行为，不用于证明线上规模或业务收益。

## 业务流程

```text
用户在中文页面提问
  -> 识别本轮任务和必要条件
     -> 条件不完整：询问并保存待继续的对话
     -> 固定指标：校验日期/分组 -> 只读参数化 SQL -> 返回数值与口径
     -> 规则解释：检索规则片段 -> 返回原文与来源编号
     -> 原始记录审计：交给 SQL 专项子流程 -> 核对执行状态/语句/结果
  -> 只展示本轮实际得到的数字、出处或明确失败原因
  -> 用户继续追问；新对话与旧对话的条件隔离
```

这三条路径不能互相替代。超时率必须使用预定义分子和分母；规则问答不能拿数据库数字充当政策解释；原始记录审计也不能暗中套用指标的排除条件。模型负责理解表达、提出结构化工具参数和参与流程，公式与最终证据由程序控制。

## 关键设计

**指标 Skill。** 支持工单数量、平均处理时长和超时率。输入为指标、UTC 起止日期、可选类别与分组；日期采用左闭右开，观察截止固定为 `2026-10-08 00:00:00 UTC`，窗口最多 93 天。参数化只读查询返回分子、分母、数值和规则版本。超时率分母包括未解决的有效工单；空集合不是零比例；分组结果不能脱离分母直接平均。超过范围、组数上限或查询失败都显示独立状态。

**资料检索。** 规则文档按章节切分，默认 BM25 检索；可选本地向量模式已有小样本单独验证。每段结果附 `source_ref`、`chunk_id`、行号和内容版本，并受 top-k 与上下文长度限制。答案展示检索原文，避免小模型再次改写口径。未命中只说明当前资料没找到相关片段，不能推断现实中不存在规则。

**会话与澄清。** 缺指标或日期时暂停询问，用户补齐后从保存的任务状态继续。同一会话可沿用已确认条件，新会话不能继承旧会话数据。“这周”需要新的时间解释，本演示要求明确 UTC 起止日期，不自动套用历史查询范围。没有本轮工具执行证据就不输出新的统计结论。

**执行约束。** 演示配置收窄工具集合，指标查询走固定 SQL，原始审计走只读 SQL 子流程；只有执行成功的本轮结果才进入答案。只读数据库连接、参数校验、结果条数限制和失败状态形成最小运行边界，但不是生产级权限隔离或完整 SQL 沙箱。原始审计路径有主对话到 SQL 专项子流程的有限职责交接；固定指标本身是单工具调用，不能说每次都有多个 Agent 协作。

## 延迟与成本

默认使用本机 Ollama `qwen2.5:3b`，无付费 API 回退。单次模型调用设置 90 秒超时、0 次自动重试、最多 384 个输出 token；固定指标不再额外调用模型重算答案。CPU 推理单步可能数十秒，SQL 子流程多步串行更慢。网页**没有**端到端超时、排队、并发限流或 p95 服务承诺，用户重复提交也不是已解决的问题。历史本机观察不构成性能基准。

## 可核对范围

离线回归覆盖口径、日期边界、只读查询、资料来源、澄清恢复、会话隔离和前端状态；真实本机网页曾核对整体 4/10、分类 3/4、0/2、1/4，规则引用及原始表 `MAX(id)=15`。替身测试不能证明模型质量，15 条样本也不能证明大规模检索效果。复现步骤见[仓库首页](../README.md)和[演示脚本](../example/support_quality/PROJECT_CASE_STUDY.md)。
