# 设计说明：工单质量分析助手

## 我能解决什么

场景：客服主管复盘某段时间的工单，想知道超时比例、哪个类别最严重、分母是否包含未解决工单，并核对原始记录。人工在多个表格/规则文档间切换容易混淆口径；直接让模型自由写 SQL 或编写解释，也可能把历史日期当“这周”、把不同类别比例直接平均、遗漏未解决工单，或编造不存在的规则。

交付目标是让一次提问从**明确范围 -> 选择能力 -> 执行真实查询/检索 -> 展示数字与依据 -> 支持追问或澄清**闭环。演示数据是 15 条完全合成的边界样本，目的在于验证正确性和失败分支，不用于证明统计规模、业务收益或线上性能。

## 请求流与职责

```text
中文 Streamlit 页面 / 会话 ID
  -> 上游 LangGraph 主助手（模型选择工具、AskHuman 暂停/恢复）
     -> 本地 support_quality Skill：参数校验 + 固定口径只读 SQL + 结构化证据
     -> 本地 search_knowledge 增强：Markdown 分块 + BM25/可选向量 + 来源引用
     -> 上游 Text2SQL 子图：针对原始记录审计的选表、生成和执行
  -> 展示本轮实际结果、规则原文/出处或明确失败状态
```

指标计算不由模型决定公式。`support_quality` 只接收指标、UTC 起止日期、可选类别与分组，使用参数化查询；开始日包含、结束日不包含，观察截止固定为 `2026-10-08 00:00:00 UTC`，窗口最多 93 天。超时率返回分子、分母、比例和规则版本；未解决的有效工单计入分母。空集合、日期越界和工具执行失败不会伪装成成功数字。原始记录审计保持用户明确的范围，不擅自附加指标排除规则。

规则问题走资料检索而非数据库聚合。Markdown 文档分块后默认 BM25；可选本地 embedding 向量模式独立验证。返回 `source_ref`、`chunk_id`、行号与内容版本，限制 top-k/上下文预算。未命中只表示当前资料未命中，不证明现实没有规定；检索错误与未命中分开。回答优先展示已检索原文，不让小模型二次改写成相反结论。

缺少范围时用 AskHuman 补齐，checkpoint 保存会话状态；新会话不能继承旧会话条件。相对时间如“这周”在本演示中**不自动换算**，必须向用户确认 UTC 日期。仅有上轮答案而没有本轮工具执行证据时，不输出新统计。工具白名单、只读 SQLite、SQL 结果条数限制与执行证据门槛构成演示级 runtime 约束，不等于生产权限或完整 SQL 沙箱。

## 延迟、成本与故障边界

默认模型是本机 Ollama `qwen2.5:3b`，无付费 API 回退；配置单次模型调用超时 90 秒、模型自动重试 0 次、单次输出上限 384 token。诊断回放另有限次/总时长限制，但网页的**完整多步请求没有端到端超时、排队、并发限流或 p95 SLA**。CPU 推理单步可达数十秒，Text2SQL 子图多步串行更慢；同一请求复用模型，不为固定公式额外生成答案。客户端应等待完成而不是重复发送；超时/失败必须显示失败，不得展示旧结果充数。

已观察到本地单次模型调用约 7-34 秒的历史浏览器记录；另一次 4 调用 SQL 回放耗时 60.69 秒。这些是特定机器、模型和案例的观察值，**不是**可复现的基准或生产性能承诺。未统计请求级 token 账本、p95、吞吐、并发用户数或外部 API 成本。以后若做生产化，应先增加每请求耗时/模型调用次数记录、端到端预算与可取消执行，再压测和按实际流量确定指标。

## 验证与能力边界

离线回归覆盖日期/口径、只读查询、规则来源、未命中、澄清恢复、会话隔离及前端状态。真实本机模型的网页演示核对整体 4/10、分类 3/4/0/2/1/4、规则来源与原始表 `MAX(id)=15`。离线替身不能证明模型质量；15 条样本不能证明大规模 RAG 或 SQL 准确率。`example/support_quality/PROJECT_CASE_STUDY.md` 逐项列出证据和局限，复现命令见根目录 README。

上游提供主图、Text2SQL 子图、checkpoint 与基础页面；本地贡献是具体业务闭环与约束。指标查询只是单工具调用；原始 SQL 才有主图到 SQL 专项子图的有限角色交接，不能宣称自研通用多 Agent 平台。此项目展示的是针对**口径漂移、证据缺失、上下文串用**三个具体问题的工程改进，而不是术语堆叠。
