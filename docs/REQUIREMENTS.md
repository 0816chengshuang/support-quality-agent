# 工单质量分析助手｜需求说明

## 1. 产品目标

客服或运营主管需要在复盘中快速回答一组连续问题：指定时间内的工单处理情况如何，哪个类别值得优先关注，统计口径是什么，数字能否回到原始记录核对。

本项目提供一个中文对话工作台，让主管用自然语言完成**指标查询、分类追问、规则查证和原始记录审计**。每次结果都带上本轮使用的时间范围、计算依据或查询来源，方便复核和继续讨论。

## 2. 用户场景

主管准备每周质量复盘。她先查看整体超时率，发现账号类比例较高，于是沿用同一时间范围按类别拆分；随后确认未解决工单是否进入超时率分母，并抽查原始表中的记录。讨论过程中，如果有人只说“这周”，系统先请对方确认 UTC 起止日期，再继续原任务。

这条流程原先要在报表、规则文档和数据查询之间切换。对话工作台把相关操作接在同一个上下文里，减少临时追问时重复描述条件、人工核对口径和寻找证据的时间。

## 3. 核心需求

| 编号 | 用户要完成的事 | 系统响应 | 用户得到的价值 |
| --- | --- | --- | --- |
| R1 | 查询工单数量、平均处理时长或超时率 | 识别指标、UTC 日期、类别与分组，使用固定口径计算，返回数值及关键计算字段 | 不同提问沿用同一指标定义 |
| R2 | 沿用已确认条件继续追问 | 在当前会话保留日期与指标，按新的类别或分组条件查询 | 复盘过程可以逐层深入 |
| R3 | 核对指标定义 | 检索规则资料，给出相关原文、章节来源与片段编号 | 每个口径问题都有可追溯依据 |
| R4 | 抽查原始记录 | 将查询交给 SQL 专项流程，展示实际执行的只读 SQL 与结果 | 统计结果可以回到数据层核对 |
| R5 | 补充不完整的问题 | 询问缺失的指标或日期，保存待继续状态；补齐后继续处理 | 减少猜测造成的错误结论 |
| R6 | 管理多段复盘对话 | 新建独立会话，并在历史列表中切回已有对话 | 不同讨论的条件和结果保持清晰 |

## 4. 业务规则

1. 所有日期按 UTC 解释，查询区间为开始日包含、结束日不包含；演示数据的观察截止为 `2026-10-08 00:00:00 UTC`。
2. 有效工单排除测试、重复及观察截止前已取消的记录。超时率分母包含所有有效工单，包括未解决及尚未到期限的工单。
3. 平均处理时长只计算观察截止前已解决的工单；没有符合条件的已解决记录时，返回空均值状态。
4. 分类比例保留各类分子与分母。整体比例按整体分子、分母计算。
5. 原始记录审计遵循用户明确提出的包含范围，执行结果同时提供 SQL 和返回值。
6. 资料未命中、日期越界、无数据及查询失败分别返回对应状态，让用户知道下一步该补充什么或检查什么。

完整定义见[指标规则](../openchatbi/skills/support_quality/METRICS.md)。

## 5. 一次完整演示的验收

演示数据为 15 条合成工单，覆盖测试、重复、取消、未解决和时间边界。按下面顺序在[本机页面](http://127.0.0.1:8501/)操作：

| 步骤 | 用户输入或动作 | 验收观察点 |
| --- | --- | --- |
| 整体 | `统计 2026-10-01（含）到 2026-10-08（不含）新建工单的超时率，使用 UTC，按整体统计，不筛类别。` | 返回 **40%（4/10）**，能看到时间和口径依据 |
| 分类 | `保持刚才日期和口径，按类别拆开看。` | 账号 **3/4**、账务 **0/2**、配送 **1/4** |
| 规则 | `超时率分母包括未解决工单吗？请查规则并给出处。` | 返回中文规则原文，带 `source_ref` 与 `chunk_id` |
| 审计 | `请查询合成工单原始表中的最大 id，包括测试、重复、已取消记录，不作业务排除、不限制日期。给出真实 SQL 和查询结果，不要图表。` | 展示实际只读 SQL，结果 `MAX(id)=15` |
| 澄清 | 新建对话后询问 `这周超时率多少？` | 要求确认 UTC 起止日期；补齐后继续查询 |
| 恢复 | 新建对话，再从左侧历史列表切回 | 已有问题、结果及待补充状态可继续查看或处理 |

其中 4/10 是有效工单统计，15 是原始表最大编号，两者回答不同的用户问题。演示样本用于核对流程与边界行为。

## 6. 交付与运行条件

交付包含中文网页、合成数据准备入口、指标规则文件、演示脚本和离线回归。默认使用本机 `qwen2.5:3b` 与 BM25 检索；指标和原始审计连接只读 SQLite。CPU 推理可能需要等待数十秒，SQL 专项流程会经历多次模型调用。

本版的验收以表中的用户流程、真实执行结果和来源展示为准。工程实现与延迟约束见[设计说明](DESIGN.md)，启动步骤见[仓库首页](../README.md)。
